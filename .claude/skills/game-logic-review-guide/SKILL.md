# 게임 로직 리뷰 가이드 — GyeongdoPlus

## 게임 기획 이해

경도플러스는 **위치 기반 실시간 경찰-도둑 게임**이다. 핵심 재미 요소:
1. GPS 기반 실제 이동과 추격
2. 직업별 특수 능력으로 전략 다양성
3. 레이더를 통한 적 위치 힌트 (완전한 정보가 아닌 방향/거리만)
4. 체포-구출 순환으로 역전 가능성

## 검증 영역

### 1. 직업 시스템 밸런스

**경찰 직업** — 체포/탐지에 특화
| 직업 | 효과 | 쿨다운 | 검증 포인트 |
|------|------|--------|------------|
| SEARCHER | 5초간 도둑 위치 공개 | 90초 | 5초가 너무 짧거나 길진 않은지 |
| JAILER | 즉시 교도소 잠금 | 180초 | 긴 쿨다운이 JAILER를 유일하게 사용할 만한지 |
| ENFORCER | 5초간 체포 속도 증가 | 150초 | 체포 속도 수치가 game.service에 명시되어 있는지 |
| CHASER | 10초간 이동 속도 증가 | 120초 | 이동 속도가 Frontend에서 반영되는지 (GPS 기반이면 의미 없을 수 있음) |

**도둑 직업** — 은신/탈출에 특화
| 직업 | 효과 | 쿨다운 | 검증 포인트 |
|------|------|--------|------------|
| SHADOW | 15초간 레이더에서 숨김 | 120초 | radar_ping에서 SHADOW 상태 도둑 제외 확인 |
| BROKER | 즉시 팀원 구출 | 160초 | 교도소 외부에서도 사용 가능한지 |
| HACKER | 9초간 경찰 레이더 교란 | 140초 | 교란 효과가 Backend에서 ping 필터링으로 구현되었는지 |
| CLOWN | 30초간 위치 랜덤 스푸핑 | 100초 | 스푸핑된 위치가 일관성 있는지 (매 핑마다 다른 위치면 이상함) |

**검증 방법**: `game.service.ts`의 `ABILITY_EFFECTS` 상수 → `events.gateway.ts`의 radar_ping 처리 → `providers/radar_provider.dart`의 ping 렌더링 흐름 추적

### 2. 체포/구출 규칙

**체포 조건 검증**
- 거리 기준이 코드에 명시되어 있는지 (예: 10m 이내)
- 체포 시도 → `captureProgress` 증가 → 100% 도달 시 체포 확정 패턴인지, 즉시 체포인지
- 체포 중 도망치면 progress 초기화되는지

**구출 조건 검증**
- 교도소 위치가 고정인지 동적인지
- 구출 가능한 플레이어 조건 (체포된 팀원만, 자기 자신 구출 불가)
- 구출 중 경찰이 방해 가능한지

**동시성 문제**
- 두 경찰이 같은 도둑을 동시에 체포 시도 → 중복 체포 방지
- 두 도둑이 같은 팀원을 동시에 구출 시도 → 중복 처리 방지

### 3. 게임 상태머신 동기화

**Backend 상태 흐름:**
```
WAITING → PREPARE (모든 플레이어 준비 완료, 호스트 시작)
PREPARE → RUNNING (준비 시간 만료, prepEndsAtMs 도달)
RUNNING → ENDED  (승리 조건 달성 또는 endsAtMs 도달)
```

**Frontend 상태 흐름:**
```
offGame → lobby (방 생성/참여)
lobby → inGame  (match_state.state == 'RUNNING' 수신)
inGame → postGame (match_state.state == 'ENDED' 수신)
```

**검증**: `match_state` 메시지의 `state` 필드 변화에 따른 Frontend Phase 전환이 정확한지.
특히 `PREP` 상태는 Frontend에서 어떻게 처리되는지 (로비에서 대기? 게임 화면으로 이동?).

### 4. 레이더 시스템

**핑 정확성 검증**
- `bearingDeg`: 0-360 범위 내 정규화 확인
- `distanceM`: 음수 값 불가 확인
- `ttlMs`: 핑 수신 후 경과 시간을 기준으로 Frontend에서 만료 처리하는지

**SHADOW 직업 처리**
- Backend에서 radar_ping 생성 시 SHADOW 상태인 도둑 위치를 제외해야 함
- Frontend `radar_provider`에서 추가 필터링이 있는지 (중복이라도 안전한지 확인)

## 검증 체크리스트 (코드에서 찾을 것)

- [ ] `ABILITY_EFFECTS` 상수가 기획 수치와 일치하는지
- [ ] 직업 효과가 실제로 게임 로직에 반영되는지 (단순 DB 저장으로 끝나지 않는지)
- [ ] 체포 거리 상수가 명시적으로 정의되었는지
- [ ] 게임 종료 조건이 Backend에서 자동 트리거되는지 (타이머 기반)
- [ ] 비정상 종료(플레이어 탈주) 시 게임이 어떻게 처리되는지

## 출력 형식

1. **요약**
2. **CRITICAL** (규칙 오류, 게임 진행 불가 버그)
3. **WARNING** (밸런스 문제, 엣지 케이스 미처리)
4. **게임 밸런스 평가** (직업 시스템 전반)
5. **미구현 기능 목록** (기획에는 있으나 코드에 없는 것)
